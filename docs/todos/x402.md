# x402 Protocol Implementation

**Priority:** Tier 3 (Bisa Nanti)
**Status:** Not Started (0/8 complete)

## Context
x402 udah ada handler-nya tapi masih ada issues: mock tx hash, recipient invalid, double broadcast, payment verification belum lengkap.

## Current State
- [ ] Jangan menghasilkan mock tx hash kecuali explicit development profile
- [ ] Jangan mengembalikan `success: true` sebelum settlement terkonfirmasi
- [ ] Recipient `"x402-facilitator-pool"` bukan address EVM valid; ganti dengan konfigurasi address nyata
- [ ] Verifikasi BLS payment sebelum queue
- [ ] Bind payment ke resource URI, merchant, network, asset, amount, dan expiry
- [ ] Tambahkan idempotency dan reservation nullifier
- [ ] Hindari double broadcast: saat ini request dimasukkan queue dan juga langsung dibroadcast
- [ ] Return payment status ID, bukan receipt palsu

## Requirements

### 1. Fix Mock/Invalid Values
- Remove mock tx hash generation (production only)
- `NIMBUS_X402_RECIPIENT` harus address EVM valid (0x...)
- Return `success: false` kalau settlement belum confirmed

### 2. Payment Verification
- Verify BLS signature sebelum enqueue
- Verify nullifier belum dipake (double-spend prevention)
- Bind payment ke resource URI + merchant + network + asset + amount + expiry

### 3. Idempotency
- Tambah `idempotency_key` field
- Cache di DB (24h TTL)
- Return same response kalau duplicate request

### 4. No Double Broadcast
- Request masuk queue dulu
- Worker proses queue
- Jangan langsung broadcast di handler

### 5. Status Tracking
- Return `payment_status_id` (bukan tx hash)
- Client bisa query status: `GET /api/x402/status?id=...`

## Acceptance Criteria
- [ ] No mock tx hash in production
- [ ] Recipient valid (EVM address)
- [ ] BLS verification before queue
- [ ] Payment binding enforce
- [ ] Idempotency works
- [ ] No double broadcast
- [ ] Status tracking works
- [ ] `cargo test` + `cargo clippy` clean
